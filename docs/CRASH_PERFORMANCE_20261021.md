# 2026-10-21 真机闪退与性能排查

设备：HUAWEI Mate 80，API 26，Maleoon 920。游戏构建：3.3.94012。

## 创建角色闪退

真机复现创建野蛮人、接受角色名称后崩溃。现场为 `main+0xa15300`：

```asm
// 函数入口 main+0xa14dc4
mov x19, x8
// 崩溃位置 main+0xa15300
strb wzr, [x22, #0x18]!
```

`svc #0x87` 转调原地上物品外观路径函数，返回值是字符串对象，AAPCS64 使用
`x8` 传递间接结果地址。原来的 C 八参数函数指针调用只传 `x0–x7`，丢失
`x8`，其值碰巧变成目标函数地址，导致向只读代码页写字符串。

`dm_guest_call_regs` 使用门帧保存的 `x0–x8`、`q0–q7`、客体 `x18` 转调，
保留整数/浮点返回值并恢复宿主 `x18`。真机已验证创建角色进入营地，以及
重启应用后读取该角色再次进局。主机 ABI 回归验证八整数参数、带边界哨兵的
间接结构体返回、SIMD 参数和返回值；并非用主机测试代替鸿蒙整局测试。

## 回放层改动

- 小于 16 字节的暂存分配保留对齐空间，但只读取原始长度并清零尾部；
  回写也限定为客体声明的长度。
- 使用翻译器反射 `sbufs.flags & 1` 判断写权限，只读存储缓冲区不回写。
  原来的无差别回写既浪费带宽，也会覆盖游戏线程的新数据、触发脏页处理。
- 确需回写时先处理目标池页的写保护。
- 合并同一描述符集合的更新，避免每个绑定单独调用 Vulkan 更新接口。
- 小范围常量/缓冲区更新只失效重叠缓存；每次提交仍清空全部快照。
- 只读缓冲区同一地址已有较大的快照时复用其前缀，维持请求的描述符长度。
- 按索引格式使用固定大小读取求最大索引，缓存一次提交中的相同索引范围；
  缓冲区重叠写入会失效该缓存。
- 原生 CPU 路径启用 `-O2`，保留帧指针。

`dm_replay_stats.txt` 增加累计 CPU 回放、描述符、暂存复制、索引扫描、GPU
等待、回写毫秒数以及暂存数据量。描述符/暂存/索引时间包含于回放时间内，
不能直接相加。帧率通过两次 `present` 差值除以主机单调时钟间隔计算，
不使用加载阶段的累计平均帧率。

目前仍保留同步提交和 GPU 完成后的资源回收。进一步实现异步提交必须同时
处理暂存池、命令缓冲区、描述符、客体事件与回写的生命周期，不能直接删除
`vkQueueWaitIdle`。
