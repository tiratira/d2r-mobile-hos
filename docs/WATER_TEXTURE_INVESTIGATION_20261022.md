# 草地小水池缺失：调查与离线修正

## 当前状态

营地红闪已由用户确认消失。本轮纹理传输修正版已通过 DevEco CLI 安装并重启，启动检查通过。用户实机确认“有水池了”，继续游玩后反馈“目前正常”。草地水池缺失已恢复。

## 有效采集与被撤回的结论

- 一份仅有 201 个启动 UI 绘制的文件曾被误当作现场数据。它不能证明游戏没有提交水面。
- 设备日志持续出现 `VK_ERROR_OUT_OF_DATE_KHR`，原回放在获取交换链图像失败后未重建，且提前打开了命令缓冲。已增加恢复流程和回归测试。
- 恢复后成功采集：`CAPTURE_START frame=3519 draws=1793454` 到 `CAPTURE_DONE frame=3521 draws=1796065`。其中有两次水面绘制。
- 后续水面几何每次有 2454 个索引、428 个顶点。基础位置投影落在视野外；平涂诊断也未在池边显示水面。尚未锁定池边水面对应的绘制。
- 贴图清除命令和整数视图曾被遗漏，已经补齐。用户反馈这处修正未恢复草地水池，不能将它认定为本问题根因。

## 本轮离线确认并修正的缺陷

1. `copyB2T` 直接将 BC 压缩块上传到已经解压成 RGBA/RG 等格式的 Vulkan 图像。现在先用现有 BC 解码器解码，再以像素行上传，覆盖最小 1×1 mip。
2. 缓冲上传和贴图间拷贝忽略视图的 mip、数组层及 image stride；数组层曾被混入 2D 图像的 Z 坐标。现在统一校验并解析复制范围，分别处理数组层与 3D 切片。
3. 等尺寸贴图拷贝一律使用 blit，可能改变整数/浮点视图的原始位。现在兼容的等尺寸复制使用 `vkCmdCopyImage`；缩放或镜像走 blit。
4. `OP_COPY_T2B` 被回放层忽略；CPU `ReadTexels` 只读取 CPU 阴影，未读取 GPU 渲染结果。现在记录 GPU 读回并在完成后发布；同次提交的后续消费者可复用 GPU 副本。
5. 原 CPU 排布读取没有正确处理 mip、多个数组层及 3D 深度，3D 解排布可能写超分配缓冲。现在按当前 mip 尺寸分配并逐层/切片复制，保留目标行和图像间填充字节。
6. 立方体纹理数组的图像层数遗漏每个立方体的六个面。现在与 Tegra 排布计算一致。

这些缺陷已由代码和离线测试确认；整组修正安装后，用户确认小水池恢复。尚未通过逐项对照将根因缩小到其中某一项。

## 验证

- `python3 tools/test_replay_cache.py`：7 项回归通过，包含交换链失败后的恢复次序。
- `python3 tools/test_texture_copy.py`：执行实际回放函数；只替换 Vulkan 驱动入口，使用真实 BC 解码和 Tegra 排布实现；通过 ASan/UBSan 检查。
- 覆盖：带行/图像 stride 的上传和延迟读回、BC1 多层上传及 1×1 mip、非零 mip/层的原始位复制、镜像、3D 上传、立方体数组/3D CPU 解排布、非法范围、整数视图清除参数。
- 组合键和遮挡计数器已有回归通过；DevEco ArkTS 检查与构建通过。

测试不等同于硬件兼容验证。压缩渲染结果重新编码读回、部分通道清除、3D 纹理清除等原本未覆盖的形态不在本轮兼容范围内。
